# Android JS 脚本执行器 — 设计文档

> 项目代号：`android-script-js`
> 定位：基于无障碍手势 + 屏幕识别的 Android 自动化脚本执行器。
> **收敛范围：坐标操作 + 图片匹配点击 + OCR 文字定位点击**，不做控件（UiSelector）类自动化。

---

## 1. 产品概述

### 1.1 目标
- 提供与桌面版（windows-script-py / JsScriptRunner）同一套心智模型：**找图 → 点击 → 等待 → 校验**。
- API 设计对标 Auto.js 的图色子集，并对齐 Windows 版参数语义（threshold / region / wait_*）。
- 移动端内置编辑器 + 悬浮调试工具，做到「写脚本 — 调试 — 运行」闭环。

### 1.2 能力矩阵
| 能力 | 原理 | 典型场景 | 权限 |
|---|---|---|---|
| 坐标操作 | AccessibilityService `dispatchGesture` 手势 | 点击、滑动、长按、多指手势 | 基础 |
| 图片匹配 | MediaProjection 截屏 + 自研模板匹配/找色（灰化 + MAD 粗筛 + NCC 精判，未用 OpenCV，见 §2.3） | 固定图样按钮、加载框等待 | 进阶 |
| OCR | MLKit 文字识别（中文模型内置）识别文字并返回坐标 | 无固定图样、文字固定的按钮 | 进阶 |

### 1.3 明确不做（保持执行器精简）
- 控件树查找与节点操作（UiSelector / UiObject）
- 声明式 UI / 对话框 / 悬浮窗自定义 UI 等界面模式
- 网络、加密、传感器、多线程、事件监听等扩展模块
  （脚本自身的 JS 能力足够覆盖简单逻辑；后续按需再加）

## 2. 总体架构

```
┌─────────────────────────────────────────────────────┐
│                     App 层 (Compose UI)              │
│ 任务管理/素材管理 │ 代码编辑器 │ 悬浮球/控制台 │ 拾取器/模板工具│
├─────────────────────────────────────────────────────┤
│                     调度与运行时                      │
│   脚本运行器(单任务串行) │ 定时任务 │ 崩溃捕获/保活    │
├─────────────────────────────────────────────────────┤
│                   JS 引擎 (QuickJS)                  │
│        注入 Bridge：全局函数 + 模块注册表(require)    │
├─────────────────────────────────────────────────────┤
│                    原生能力层 (Kotlin)                │
│ AccessibilityService(仅手势) │ MediaProjection │      │
│ 自研匹配(找图/找色) │ MLKit OCR │ libsu可选 │
└─────────────────────────────────────────────────────┘
```

### 2.1 模块划分
> **实现现状**：工程为**单 Gradle 模块 `:app`**，下表各项以**包**的形式落地（`com.script.js.core.*`），未拆分为独立 Gradle 模块；`docs/API_REFERENCE.md` 即 `:api-docs` 的产物（`core/editor/ApiDocs`）。这样可避免多模块在 AGP 9 + 内置 Kotlin 下的构建复杂度，需要时按此表拆分即可。

| 模块 | 职责 | 实现位置 |
|---|---|---|
| `:app` | Compose UI、脚本管理、编辑器、悬浮球/控制台、坐标拾取器、取色器、模板截取工具 | `MainActivity` / `ScriptEditorActivity` / `TemplateCaptureActivity` / `core/floaty/*` |
| `:core-engine` | QuickJS 封装、Bridge 注入、脚本生命周期、全局函数（sleep/exit/log 等） | `core/engine/*` |
| `:core-gesture` | 无障碍服务、`dispatchGesture` 手势派发（click/swipe/gesture），不做控件树解析 | `core/gesture/*` |
| `:core-image` | MediaProjection 截屏、自研模板匹配、找色、多点找色、Root/Shizuku 静默通道 | `core/image/*`、`core/shell/RootShell` |
| `:core-ocr` | OCR 封装与坐标映射。**实现采用 MLKit 中文识别**（模型内置 APK，约 10MB）；PaddleOCR 需额外 15-20MB 模型，暂不内置（`engine: "paddle"` 会回退到 MLKit） | `core/ocr/OcrApi` |
| `:api-docs` | API 定义与 `.d.ts` 声明文件（编辑器补全用） | `core/editor/ApiDocs` + `docs/API_REFERENCE.md` |


### 2.2 脚本执行模型
- **单任务串行**（**已实现**，与最初设想的多脚本并行不同）：同一时刻只运行一个任务，重复触发（手动连点/定时到点撞上手动运行）会被跳过并写日志「已有任务在运行，跳过: <任务>」。原因：手势派发、截屏通道、悬浮控件状态都是**进程级独占资源**，两个脚本并发派发手势会互相干扰点击目标，反而降低可靠性；定时任务与手动任务共用同一条串行队列（`ScriptRunner._state.running` 作为闸门）。如需并行，建议按任务分进程（`android:process`）后再放开闸门。
- 每个脚本 = 一个独立 QuickJS 实例（隔离作用域），循环执行时可复用同一实例。
- 坐标 API 同步阻塞调用（内部派发手势并等待完成），符合脚本顺序执行心智。
- 找图/OCR 为同步调用，底层在服务线程执行，宿主停止按钮触发引擎中断。
- 异常统一捕获 → 写入运行日志 → 悬浮控制台展示；`try/catch` 可在 JS 侧捕获。
- 素材路径：相对路径基于**任务目录**解析（`images/` 子目录，与 Windows 版脚本目录约定一致）。

### 2.3 关键技术选型
| 项 | 选型 | 说明 |
|---|---|---|
| JS 引擎 | QuickJS | 启动快、内存小；补齐 Promise/async、console、require |
| 手势 | AccessibilityService.dispatchGesture | 无需 Root；不支持手势的老设备降级 Root `input` |
| 截屏 | MediaProjection (ImageReader) | 系统授权弹窗一次；Root/Shizuku 可静默截屏 |
| 匹配 | 纯 Kotlin 模板匹配（灰化 + MAD 粗筛 + NCC 精判） | 相邻命中聚合；**不引入 OpenCV**：其 AAR 约 117MB（APK 会从 13MB 涨到 80MB+），MVP 用自研由粗到细匹配即可满足固定图样点击；后续需要多尺度/复杂找色时再替换为 OpenCV |
| OCR | MLKit 中文文字识别 | 模型随 APK 内置（无需下载）；PaddleOCR/PaddleLite 未内置（+15-20MB），如需更强中文精度可后续替换 |

## 3. 权限模型（分级）

| 级别 | 权限 | 解锁能力 |
|---|---|---|
| 基础 | 无障碍服务 + 悬浮窗 | 坐标点击/滑动/手势 |
| 进阶 | + MediaProjection | 截屏、找图找色、OCR |
| 增强 | + Root 或 Shizuku | **已实现静默截屏**：Root 走 `su -c screencap`，Shizuku 走 UserService（shell 身份执行 screencap）；均不可用时自动降级 MediaProjection（需授权一次）。**已实现 `input` 稳定点击兜底**：无障碍手势派发失败（服务不可用/被拒/超时）且设备有 Root 时，改用 `su -c input tap\|swipe` 完成，并在运行日志标注「[增强通道]」；折线手势 `gesture` 退化为直线滑动。无 Root 时行为与原来一致（返回 false）。 |

**Shizuku 通道实现要点（**已实现并实测**）**：
- Shizuku 13 起 **UserService 不是 Android Service**：Shizuku（shell 身份）的 starter 会反射实例化目标类并要求实例本身是 `android.os.IBinder`。因此 `core/image/ShellUserService` 必须直接继承 AIDL 生成的 `IShellService.Stub`（Stub 即 Binder），**且无需在清单里声明 `<service>`**。早期写成 `Service` 子类会在 Shizuku 侧报 `ClassCastException: ... cannot be cast to android.os.IBinder`，本应用的表现为 `Shizuku UserService 绑定失败`。
- 权限入口（**已实现**）：仅「服务在运行但未授权」这一状态需要用户动作。截屏通道对话框会显示 `Shizuku：未授权` 并给出「申请 Shizuku 权限」按钮；申请结果通过 `Shizuku.addRequestPermissionResultListener` 回调，授权成功后立即刷新通道为 `SHIZUKU` 并写运行日志，**无需重启应用或脚本**。被拒绝过之后 Shizuku 不再弹窗，界面提示到 Shizuku 应用内手动授权。
- 静默通道不做「假成功」：`ScreenCapture.requestBlocking()` 对 Root/Shizuku 会**实地截一帧确认可用**，失败则把该通道标记为不可用并降级 MediaProjection，避免出现「声称无需授权但截不到图」。主界面「截屏」芯片在静默通道可用时同样显示 ✓（不需要 MediaProjection 授权）。


无障碍掉线检测与**自动重试拉起**（**已实现**，`core/gesture/AccessibilityGuard`）：应用启动后每 2s 检测服务连接状态，并区分三种情况，避免误报刷屏（**这是修复过的缺陷**）：
- **瞬时重绑不提示**：`onUnbind` 常由系统重绑或第三方无障碍连接（如 uiautomator）触发，实测约 1s 后自动重连，因此设 **6s 宽限期**，宽限期内**完全静默**（仅一条 debug 日志「瞬时重绑 N ms（忽略）」，不写运行日志、不弹提示）；
- **设置里仍开启但连不上**（系统重连中）：只写一条警告日志，**不弹「去设置重开」**——打开设置页解决不了问题，且多数会自愈；
- **设置里已关闭**：才提示「无障碍服务已关闭，坐标点击不可用；请在『设置 → 无障碍』开启」，并在**有任务运行**时自动打开设置页引导（30s 冷却，持续掉线按冷却周期重试并计数）。
同类提示另有 60s 冷却。历史实现的问题：服务 `onInterrupt`（系统常规回调）与 `onUnbind` 都直接 Toast「请到设置重新开启」，且守护进程再报一次，导致同一次抖动弹两次错提示、被误认为「权限一直断开」。注：Android 不允许应用自行开启无障碍服务，故“拉起”实现为自动引导 + 重开后自动恢复；主界面「权限状态」页另提供手动入口。
录屏授权失效（切屏/息屏）时脚本内找图返回失败并**自动重新请求**（**已实现**）：`captureScreen()` 取不到帧且投影未就绪时，引擎自动调用一次截屏申请（每轮运行最多一次，避免反复弹窗），授权成功后当次调用即可拿到帧，失败则返回 null 并写指引日志。

## 4. 宿主 App 功能

### 4.1 任务管理
**任务（Task）= 入口脚本 + 素材 + 配置**，是 App 内的一等公民，取代松散的脚本文件：

```
tasks/
└── 每日签到/                 # 任务目录（任务名即目录名）
    ├── task.js               # 入口脚本（固定名，点击任务即运行）
    ├── config.json           # 任务配置
    └── images/               # 模板素材
        ├── confirm.png
        └── loading.png
```

```json
// config.json
{
    "name": "每日签到",
    "desc": "打开目标APP完成签到",
    "target": "com.example.app",
    "designSize": [1080, 1920],
    "loop": { "count": 1, "interval": 5 }
}
```

| 配置项 | 说明 |
|---|---|
| `name / desc` | 任务名 / 描述（展示用） |
| `target` | 目标应用包名：运行前自动拉起，可作为运行前置条件 |
| `designSize` | 可选：基准分辨率 `[w,h]`。**已实现**：`TaskManager` 解析该字段，`ScriptRunner` 在每次运行前自动 `adapter.setDesignSize(w,h)`（脚本内仍可调用 adapter 覆盖），坐标 API 与找图/找色返回值均按此基准换算 |
| `loop` | 可选：`{count, interval}` 脚本正常退出后自动循环执行 |

- **新建任务**（**已实现**）：首页「+」→ 输入名称 + **选择脚手架**（`TaskManager.Scaffold`：**空白** / **签到模板** / **找图演示**，对话框内显示各自说明）→ 按脚手架生成目录结构（后两者自动创建 `images/` 并写入 `designSize: [1080,1920]`，配置 desc 也随脚手架填写）→ 创建后可点「⋮ → 编辑脚本」进入编辑器。
- **素材管理**：任务详情页网格展示 `images/` 图片，支持：
  - **屏幕截取**：调起模板截取工具 → 框选 → 直接存入当前任务 `images/`（找图素材一键制作）；
  - **相册导入、重命名、删除、预览与尺寸信息**（**已实现**）：素材对话框支持 SAF「从相册导入」（自动去重名）、逐项「重命名」（校验非法名/重名，保持扩展名）、点击条目「预览」（缩放解码展示图片）并显示 `宽×高 · 大小`（按位图头解析，非图片文件显示「尺寸未知」）。
- **导入导出**：任务整体 zip 导入/导出（脚本 + 素材 + 配置一体迁移，可分享）。**已实现**（`core/task/TaskZip`）：
  - 导出：任务目录整体打包为 zip（保留相对路径）到外部私有目录 `files/zip/`，界面提供「分享」（FileProvider）；
  - 导入：SAF 选择 zip → 解到临时目录校验（必须含 `task.js`，兼容内容位于单层子目录）→ 任务名取自 `config.json` 或文件名并做净化 → 导入为新任务；
  - 安全：拒绝含 `..`/绝对路径的条目（防 zip-slip），同名任务已存在时拒绝导入，避免覆盖用户数据。
- **运行历史**：每个任务独立记录（耗时、退出原因、异常堆栈）。**已实现**（`core/task/RunHistory`）：
  - 记录写入任务目录 `history.jsonl`（每行一条，自动保留最近 50 条）；字段：时间、来源（手动/定时任务）、退出原因（完成/退出/已停止/出错）、耗时、错误消息、异常堆栈；
  - 任务 ⋮ 菜单「运行历史」查看：结果按级别着色、附错误消息与前几行堆栈，支持「清空历史」。

### 4.2 内置任务
- App `assets/tasks/` 预置官方任务（**手势演示、找图演示、签到脚手架**），**首次启动复制**到用户任务目录，可自由编辑；删除后下次启动会自动补回。
- App 升级不覆盖用户已修改的任务；**已实现「重置内置任务」**（`TaskManager.resetBuiltin`）：任务 ⋮ 菜单仅对内置任务显示「重置为官方版本」，二次确认后删除当前目录并从 assets 重新复制（脚本/配置/素材一并恢复官方版）。
- 内置任务同时充当**官方示例与 API 教学**，新用户开箱即跑。

### 4.3 代码编辑器
- **语法高亮、自动缩进、括号匹配**（**已实现**）：高亮为自研轻量 tokenizer（关键字/字符串/注释/数字/内置 API），未采用 Sora Editor（需内置 TextMate 语法包，且新版以 Kotlin 2.4 编译、与 AGP 内置 Kotlin 2.2 元数据上限冲突，见 §2.3）；**自动缩进**回车沿用上一行缩进、上一行以 `{`/`(`/`[` 结尾时再进一级，闭合符自动独占一行；**括号匹配**对 `(` `[` `{` `"` `'` 反引号自动配对，光标后已是同名闭合符时直接越过不重复插入。多字符变更（粘贴）原样放行。
- API 自动补全：由 `:api-docs`（`core/editor/ApiDocs`）生成 `.d.ts` 注入；编辑器按光标前缀过滤候选并插入片段（仅在输入了标识符前缀时显示，避免误触插入）。
- **错误行定位**（**已实现**）：引擎从异常消息解析 `文件:行号:列`（`ScriptEngine.parseErrorPosition`），运行器暴露 `lastError`（任务/行/列/消息）；打开编辑器时把光标定位到该行、以浅红底高亮该行，并在顶部提示条显示「上次运行第 N 行出错：<消息>」（无错误时不显示）。

### 4.4 悬浮与调试工具
- **主界面信息架构（已实现）**：四个分区各占一个 Tab——**权限状态 / 工具 / 任务 / 日志**。
  - 「权限状态」：能力三行（手势无障碍、悬浮窗、截屏）各含用途说明与状态（已开启/已授权/可用 或 红点+去授权），外加「运行状态」卡（当前任务 / 空闲，运行中可直接停止）；
  - 「工具」：取坐标、取颜色、悬浮日志、显示/隐藏悬浮球（各带一句用途说明），外加「截屏通道设置」入口（显示 `模式：AUTO 实际通道：SHIZUKU`）；
  - 「任务」：任务列表（名称 + 描述/目标应用副标题 + 运行/停止 + ⋮ 菜单）与新建/导入入口；
  - 「日志」：整屏实时日志（等宽、按级别着色、自动滚底）与「清空」。
  - 采用 Tab 的原因：竖屏下权限与工具卡片会挤占任务列表（实测列表只剩 2 行），分区后任务页可完整展示；宽屏下内容以 `widthIn(max=840dp)` 居中，避免行被拉伸。
- **默认自动开启（已实现）**：首次启动若未授权悬浮窗，自动跳转系统授权页（只引导一次，标记持久化），并写日志/Toast 说明；授权后回到界面即**自动显示悬浮球**。用户主动「隐藏悬浮球」会持久化，之后启动不再自动弹出。
- **悬浮球后台保活（已实现）**：悬浮球启用时启动 `FloatyForegroundService`，提供可关闭悬浮球的常驻通知；模拟器/系统重建服务后重新挂载浮层。用户隐藏悬浮球或撤销悬浮权限时停止该服务。
- **悬浮球（已实现，样式重设）**：悬浮窗自成一套深色视觉（不跟随 App 主题，保证在任何应用之上可读）。
  - 空闲态：52dp 圆球「JS」+ 右下角 10dp 状态点（绿=就绪），整体 92% 不透明减少遮挡；
  - 运行态：就地变圆角胶囊 = 状态点 + 「▶ 任务名」（超 8 字截断）+ **实时计时 mm:ss** + 红色「■ 停止」；
  - 交互：拖动移动、松手贴最近左右边缘、位置持久化；旋转/换分辨率后按**实际宽高收紧到屏幕内**（不丢弃位置）；圆球↔胶囊宽度变化时自动向内展开避免被裁；任务结束回到空闲态时贴回边缘。
- **悬浮面板（已实现，卡片式）**：头部「选择任务 + 数量 + ✕」，中部任务列表（46dp 行、▶ 强调色、运行中任务高亮并带绿色「运行中」标签、其余置灰、可滚动至 42% 屏高），底部工具胶囊行（取坐标 / 取色 / 去截图 / 日志 / 贴边）；运行中额外显示整行红色「■ 停止当前任务」。面板贴悬浮球同侧并对屏幕边界钳位。
- **悬浮控制台（已实现，布局重设）**：
  - 标题栏：`日志 (N)` + 清空 + ✕，**整条标题栏可拖动**，位置持久化（越界收紧）；
  - 筛选行：[全部][信息][警告][错误]，选中态高亮，标题显示 `日志 (筛选数/总数)`；
  - 日志区：等宽字体、级别着色（E 红 / W 琥珀 / D 灰），**仅当用户已在底部时才自动滚到底**（向上翻阅不被打断）；
  - 底部运行态条：`▶ 任务名 · mm:ss` + 「■ 停止」，空闲时隐藏；
  - 默认停在下半屏居中，宽 `min(屏宽-20dp, 520dp)`。
- **坐标拾取器**：屏幕上取点，自动生成 `click(x, y)` 代码并复制。
- **取色器**：取像素颜色，生成 `findColor` 颜色串；单击一次即出结果（取样未返回时自动补确认）。
- **框选截图**：悬浮层拖拽框选屏幕区域 → 隐藏选择层后抓屏裁剪 → 可编辑文件名并保存到 `screenshots/`；保存路径写入运行日志。
- **模板截取工具**：截屏 → 框选区域 → 命名（默认 `tpl_HHmmss.png`）→ 存入当前任务 `images/` 目录（与素材管理联动，对齐 Windows 版工作流）。

### 4.5 调度与稳定性
- 定时任务（WorkManager）到点拉起：**能力预置 → 按 `config.json` 拉起目标应用 → 执行任务**（**已实现**，`ScriptRunner.preflightCapabilities`，仅定时触发时执行）：
  - **无障碍未开启**：写指引日志并尝试自动打开无障碍设置页（复用 `AccessibilityGuard`）；受后台启动 Activity 限制，若未能出现在前台则在日志中给出"手动开启：设置 → 无障碍 → JS脚本执行器"的指引，脚本侧 `auto.waitFor` 仍会等待/超时。
  - **无截屏能力**（未授权录屏且无 Root/Shizuku 静默通道）：**明确降级**——不做后台弹窗尝试（系统禁止后台弹授权窗），`requestScreenCapture()` 直接返回 `false` 并写入指引日志，脚本据此跳过找图/找色步骤（避免阻塞等待一个不会出现的弹窗）。
- **前台 Service 保活 + 状态自检**（**已实现**，`core/runner/ScriptForegroundService`）：任务运行期以前台服务（`foregroundServiceType=specialUse`）常驻，低优先级常驻通知展示「脚本运行中：<任务>」与能力自检结果（无障碍✓/✗、截屏✓/✗），并提供「停止」动作（通知栏即可停止，与悬浮条等价）；任务结束/被停止时自动 `stopSelf`。API 33+ 在首次启动时申请通知权限，否则保活通知不可见。
- 全局异常钩子：脚本崩溃自动记录并提示。

### 4.6 打包（V3，可选）
- 选择任务 → 打包为独立 APK（内嵌运行时 + 脚本 + 素材）。**已实现**（`core/pack/ApkPackager`）：
  - 以**已安装的本应用 APK**作为运行时模板（无需额外准备模板），注入 `assets/task/{task.js,config.json,images/*}`；
  - 保留原 STORED 条目的压缩方式并做 4 字节对齐（`resources.arsc` 强制要求），再经 apksig 用内置调试证书（PKCS12）重签（v1+v2）；
  - 导出包启动时由 `EmbeddedTask` 提取内嵌任务到任务目录（不覆盖已有任务）并在首次启动自动运行一次。
- 实现注记：需 `packaging { jniLibs { useLegacyPackaging = true } }`（native 库安装时解压），否则重打包后对齐丢失会导致 `INSTALL_FAILED_INVALID_APK`；Android 不支持 JKS 密钥库，故内置 PKCS12 格式证书。

## 6. 风险与对策
| 风险 | 对策 |
|---|---|
| 各厂商无障碍/后台限制 | **已实现**：「权限状态」页点「手势（无障碍）」行打开「保活指引」（电池优化/自启动/锁定后台等 5 条）+ 一键打开应用设置；**掉线检测 + 自动重试拉起**见第 3 节（区分瞬时重绑/系统重连中/设置里被关闭，仅最后一种才提示并引导重开） |
| 手势点击被风控 | `clickRandom` 随机偏移 + 随机时长；滑动轨迹加抖动 |
| 老设备/服务被回收导致手势不可用 | 有 Root 时自动降级为 `su -c input tap\|swipe`（可用性与降级原因写入运行日志）；无 Root 时按原行为返回 false 并由脚本兜底。**验证状态**：Shizuku 通道成功路径已在模拟器实测通过（Shizuku 13.6.0 + adb 启动，见 docs/COVERAGE.md「验证复现步骤」）；Root 通道两段命令（`screencap -p`、`input tap`）已在 root 上下文实测生效，**应用内 Root 成功路径仍需带 `su` 的真机**（模拟器 `/system` 只读、无法注入 `su`），复现步骤见 COVERAGE.md。 |
| 截屏授权一次性/易失效 | 已提供 Root/Shizuku 静默截屏增强通道（AUTO 模式按 Root→Shizuku→MediaProjection 优先级自动选择，显式指定但不可用时降级并记录日志）；MediaProjection 失效后脚本内可重新 requestScreenCapture |

| 定时任务后台运行的能力限制 | 后台无法弹出录屏授权窗：定时触发时前置检查到无截屏能力即**直接降级**（不阻塞、返回 false + 指引日志），脚本跳过找图/找色；无障碍未开启则自动引导重开；建议定时任务改用 Root/Shizuku 静默截屏或在应用内预授权 |
| OCR 模型体积 | 采用 MLKit 中文识别（模型内置，debug 通用包含 4 个 ABI 的 native 库，包体增量较大；发布时按 ABI 拆分或 app bundle 可显著减小）；PaddleOCR 需 15-20MB 模型故未内置 |
| 多分辨率适配 | `adapter.setDesignSize` 基准坐标缩放 + 模板多尺度匹配（V2） |
| Windows 版迁移成本 | API 语义对齐（见 API_REFERENCE.md 第 7 章映射表） |
